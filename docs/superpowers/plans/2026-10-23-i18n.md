# Internationalisation fr/en de gld : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gld s'affiche, répond et s'exprime en français ou en anglais selon la clé `language` de `~/.claude/settings.json`, avec 576 verbes d'attente par langue.

**Architecture:** Le serveur Go lit `language` (cache sur mtime), le résout en `fr`/`en`/`other`/vide, l'expose dans `GET /api` (`lang`) et traduit lui-même ses textes via `go-i18n` (catalogues embarqués). Le front résout sa langue (serveur, sinon navigateur, sinon `fr`) et traduit via `react-i18next`.

**Tech Stack:** Go 1.26 (`github.com/nicksnyder/go-i18n/v2`, `golang.org/x/text/language`), React 19 + Vite + vitest, `i18next`, `react-i18next`, `jsdom` + `@testing-library/react` (dev).

**Spec:** `docs/superpowers/specs/2026-10-23-i18n-design.md`

## Global Constraints

- Répertoire de travail Go : `/home/mwinandy/Projets/glaude-code/gld` (module `gld`, paquet `main`). Front : `gld/ui`.
- Bibliothèques reconnues, aucun chargeur ou moteur maison. Vérifier l'API exacte de `go-i18n`, `i18next` et `react-i18next` via Context7 avant d'écrire du code.
- Clés anglaises hiérarchiques ; `fr.json` et `en.json` ont exactement les mêmes clés, aucune valeur vide.
- Le français reste identique à l'existant, mot pour mot (guillemets « », espaces insécables). Les tests Go et vitest existants passent sans modification de leurs attentes.
- Résolution : `fr`→fr, `en`→en, autre langue→`en` (UI, erreurs), absent→navigateur côté front, `fr` côté Go. La CLI essaie `LC_ALL` puis `LANG` avant `fr`. Prompts des helpers : consigne dans la langue résolue, langue de réponse = valeur brute de `language` si définie.
- Pas de commentaire dans le code servi au client. Commentaires de source permis, succincts, un *pourquoi*.
- Commits `type(scope): description` en français, scope `i18n` (ou le fichier visé), sujet seul, aucun trailer, jamais de `git push`, jamais `git add -A` (ajouter les fichiers par nom : d'autres sessions travaillent dans le dépôt).
- Tests ciblés (`go test -count=1 -run <Nom> .`, `npx vitest run <fichier>`). Une seule passe complète du paquet Go, dans la dernière tâche.
- Ne pas committer `gld/ui/dist`. Ne pas toucher aux fichiers modifiés par d'autres sessions (`git status` avant chaque commit).
- Interdit pour les sous-agents : `git push`, `doctrine`/migrations, tout `rm` à chemin construit depuis une variable.
- Jauge de migration front (doit tendre vers 0) : `grep -rEc '>[^<>{}]*[a-zéèàç]{3,}[^<>{}]*<|(title|placeholder|aria-label)="[^"{]*[a-zéèàç]{3,}' ui/src --include=*.tsx | grep -v ':0'`.

## Review Focus

- `settings.json` illisible, JSON invalide ou `language` non texte : langue vide, français, aucune panique (Task 1).
- `language: "Spanish"` : UI et erreurs en anglais, helpers priés de répondre en `Spanish` (Tasks 1, 2, 7).
- Changement de `language` pendant que gld tourne : le serveur le voit au prochain appel, le front au prochain rafraîchissement de `/api`, sans rechargement (Tasks 1, 2).
- Pluriel : `0`, `1`, `2` éléments donnent la bonne forme dans chaque langue (en français 0 est singulier) (Tasks 1, 3, 5).
- Clé absente ou fuite d'un identifiant brut (`session.delete`) à l'écran (Tasks 1, 2, 15).
