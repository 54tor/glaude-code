# IDE web intégré à gld : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un espace de travail « arborescence + éditeur Monaco à onglets + terminal » par dossier de projet dans gld, avec API fichiers confinée, index du projet, détection de conflit et droits `fs_read` / `fs_write`.

**Architecture:** Backend Go (`gld/ide_*.go`) : routes fichiers confinées par `os.Root` + vérification de liens symboliques, indexeur borné, observation `fsnotify` diffusée en SSE. Front React (`gld/ui/src/components/ide/`) : Monaco isolé dans un chunk `lazy`, état d'onglets en réducteur pur testable. Les droits entrent dans l'ACL multi-utilisateur existante (migration signée).

**Tech Stack:** Go 1.26 (`os.Root`, `net/http`, `github.com/fsnotify/fsnotify`), React 19, Vite (Rolldown), `monaco-editor` (npm, local), `@xterm/xterm` existant, vitest, i18next.

**Spec:** `docs/superpowers/specs/2026-10-24-ide-design.md`

## Global Constraints

- Le dossier racine est un **chemin absolu** passé en paramètre `dir`, accepté seulement s'il est un dossier de travail connu de gld (voir Task 3). Le spec parle de `project=` : c'est `dir=` partout (les racines de gld sont des dossiers, pas des identifiants).
- Droits : `fs_read` et `fs_write` (distincts de `mem_*`, `exec`). `fs_write` implique `fs_read` côté UI seulement ; chaque route teste son propre droit.
- **Aucune liste de refus** de fichiers (`.env`, clés, `.git/` ouvrables). Garde-fous : aucun `os.Walk`/`filepath.Walk` hors de l'indexeur ; un `ReadDir` par requête d'arbre ; aucun lien symbolique suivi, ni listé comme dossier, ni ouvert, ni écrasé (tout composant du chemin est `Lstat`é).
- Limites : fichier ≤ 2 Mo (`ideMaxFile = 2 << 20`), arbre ≤ 5000 entrées par dossier (`ideMaxEntries`), index ≤ 20 000 entrées, profondeur 12, 5 s (`ideIndexLimits`), 300 fichiers / 100 Ko chacun / 5 Mo cumulés alimentés à Monaco.
- Ignoré par l'index : tout nom commençant par `.`, `vendor`, `node_modules` (dossiers et fichiers, à tous les niveaux).
- Corbeille : `<dir>/.gld-trash/<unixnano>/item` + `from` (chemin d'origine), `.gld-trash/.gitignore` = `*` écrit à la première suppression. Pas de purge automatique.
- Monaco servi par gld, jamais par un CDN ; workers importés par Vite (`?worker`), même origine (CSP `script-src 'self'`). Chunk `lazy`.
- Textes : toute chaîne visible en `fr` **et** `en` (Go : `locales/{fr,en}.json`, clés `srv.ide.*`, usage `L("srv.ide.x")`/`terr`; UI : `ui/src/i18n/{fr,en}/ide.json`). Les tests de symétrie existants doivent passer.
- Toute route nouvelle : entrée dans `routeRights` (`gld/auth_acl.go`) dans le même commit (`TestEveryRouteClassified` échoue sinon).
- Aucun commentaire dans le HTML/bundles servis. Commentaires de source : un *pourquoi* non évident, jamais le fonctionnement d'une bibliothèque.
- Bibliothèques reconnues, pas de code maison pour ce qu'elles font (éditeur, diff, notifications de fichiers).
- **Checkout partagé** : commits `type(scope): description` en français, scope `ide` (ou `auth` pour Task 1-2), sujet seul, **aucun trailer ni mention d'outil**, jamais de `git push`. Ne stager que ses propres hunks (`git add -p` / `git apply --cached --unidiff-zero`), jamais `git add -A` : `gld/auth_acl.go` et d'autres fichiers portent déjà des modifications non commitées d'autrui.
- Builds ciblés, `-p 4` au plus : `go test -p 4 -count=1 -run '<Nom>' .` depuis `/home/mwinandy/Projets/glaude-code/gld` ; côté UI `npx vitest run <fichier>` depuis `gld/ui`. Pas de `go test ./...` complet ni de `npm run build` avant Task 12.
- Ne jamais lancer `doctrine`-like migrations sur la vraie base : les tests créent leur base temporaire (`openAuthStore` avec `t.TempDir()`).

## Review Focus

- Chemins hostiles : `a/../../etc/passwd`, `/etc/passwd`, `x\x00y`, chemin vide, `.` — jamais de lecture ni d'écriture hors racine, réponse 4xx sans fuite du chemin réel (Task 3, 4, 5).
- Lien symbolique **vers l'intérieur** de la racine comme composant intermédiaire ou final : listé `symlink`, ni ouvert, ni écrit, ni indexé (Task 4, 5, 6).
- Fichier supprimé ou remplacé par l'agent pendant l'édition : l'enregistrement répond 409 `conflict` (avec `deleted: true` si absent), jamais de recréation silencieuse (Task 5, 9).
- Dossier géant (> 5000 entrées) ou projet > 20 000 fichiers : réponse bornée, `truncated`/`partial` signalés, pas de blocage (Task 4, 6).
- Fichier binaire, UTF-8 invalide, fins de ligne CRLF : binaire refusé en lecture (415), CRLF restitué à l'octet près après un aller-retour enregistrer/relire (Task 4, 5, 9).
