Sessions

Find "yesterday's session", reread it, resume it or write to it without opening a terminal, and lose nothing when the machine restarts.

Find a session

  • The home page shows your sessions from the last 7 days, grouped by project. A green dot marks the ones that are open right now.
  • The search (/ key) looks through titles and conversation text.
  • The Open sessions view shows sessions active within the last hour: resuming them now costs less, because Claude's context cache is still warm.
  • Each session shows its size in tokens; the project folder is displayed under the title.

Reread and resume

  1. Click a session to reread it in full. Tool calls are collapsed to keep the conversation readable.
  2. Click Resume to reopen it in a terminal, with a starting message if you like.
  3. To act on one or several sessions: right-click, or Shift+click to select a range. You can rename, export as Markdown, move (to another project folder) or delete.

A deleted session is not lost: it goes through a trash.

The project view

Clicking a folder in the sidebar opens the project view: all its sessions, grouped by date, and what you need to drive it.

  • Git state: branch, modified and untracked files, commits ahead, and a Push button.
  • Notepad: a checklist specific to the project. Each note can become a new session (New session with the note) or be sent to a session that is already open (Send to an open session).
  • Project memory: number of files and tokens loaded at each session (see Memory and rules).
  • The project's Permissions and the Workspace in one click; Resume the recent ones reopens the folder's latest sessions.

Write to a session without a terminal

From the reader, type a message: Claude replies in the page. If the session is already running in a tmux terminal, the Send to the session button writes straight into it, and you watch what Claude is doing live.

Cost. Each message sent this way reloads the whole context: expect roughly $1 to $2 per message on a cold session. The "warm cache" view exists precisely to spot the cheap sessions to restart, and Glaude Code announces the cost of a send on a cold session.

Send while Claude is working

A message goes out immediately, even while Claude is working. The send button's menu offers:

  • Send, interrupting: the current reply stops and the message goes through.
  • Wait until idle (checkbox remembered per session): the message is only sent once Claude is waiting.

A pending question (Claude asks you for a choice or an authorization) always queues the message: it goes out once the question is handled. The Background button sends Ctrl+B to the tmux session to move the running task to the background.

Start a new session

The New session button (first in the navigation bar) asks for the starting message and the folder: the browser lists your recent projects first. To limit which folders can be browsed, see Restrict the folder browser.

Lose nothing on restart

Glaude Code records the open sessions every 2 minutes. After the machine restarts, Reopen all relaunches them, each in its own tab. From the command line:

gld matin             # reopens a project's sessions
gld matin --resume    # reopens the last save

Several configuration folders

If you have several Claude configuration folders (for example one for work, one for personal use), the selector at the top of the sidebar lets you add some, remove some from the list and switch between them. Each folder has its own sessions, memory and settings.

Security reviews

Sessions launched by skills (security reviews) are hidden from the other views and from saved workspaces, and grouped in a Security reviews view (at the bottom of the sidebar), with a Clean up button.
