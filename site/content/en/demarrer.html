Install and get started

A single binary that embeds the interface. Only Claude Code has to be installed already: Glaude Code (the gld command) reads the ~/.claude folder and sends nothing anywhere else.

Install the release binary

Pick the file for your system on the latest release: gld-linux-amd64, gld-linux-arm64, gld-darwin-arm64, gld-darwin-amd64, gld-windows-amd64.exe… The full list and the SHA256SUMS file are on that page. You need neither Go, nor Node.js, nor make.

Example for Linux amd64, verifying the origin and the checksum:

curl -LO https://github.com/54tor/glaude-code/releases/latest/download/gld-linux-amd64
curl -LO https://github.com/54tor/glaude-code/releases/latest/download/SHA256SUMS
gh attestation verify gld-linux-amd64 --repo 54tor/glaude-code
sha256sum --ignore-missing -c SHA256SUMS
chmod +x gld-linux-amd64 && mv gld-linux-amd64 ~/.local/bin/gld
gld --version

The ~/.local/bin folder must be in your PATH.

Build from source

You need Go 1.25 or newer, Node.js and Claude Code already installed.

git clone https://github.com/54tor/glaude-code
cd glaude-code
make install

The gld command is installed in ~/.local/bin.

Run it

gld

Then open http://127.0.0.1:8799 in your browser. That's all: by default, the page is only reachable from your own computer.

To open it from a phone or another computer, see Phone and remote access.

Port already in use

If port 8799 is taken, pick another one:

GLD_WEB_PORT=8800 gld

Choose the language

Glaude Code speaks French and English. The language comes from the language setting in ~/.claude/settings.json, the same one Claude Code uses; you change it on the Configuration page.

  • French or fr gives French, English or en gives English.
  • Any other language gives the interface in English; the automatic titles, explanations and drafts requested from Claude follow your setting.
  • With no setting, the interface follows the browser language, the gld-* commands follow LC_ALL then LANG, and the server speaks French.
  • The content of your sessions, memories, skills and snippets is never translated.

Windows

Windows support is compiled but not yet tested on a real machine. Without tmux, gld.exe cannot write into a session that is already open (only resuming with a message works) and agent teams are refused. WSL2 is the recommended route.

With WSL2 (recommended)

Under WSL2, the Linux version works as is, tmux included. Everything is installed inside the Linux distribution, not on the Windows side.

  1. In PowerShell: wsl --install, then restart.
  2. In WSL, install Claude Code (the native installer needs neither Node.js nor Python) and tmux: sudo apt install tmux.
  3. Install the gld-linux-amd64 binary as above and check that ~/.local/bin is in the PATH.
  4. Run gld in WSL, then open http://127.0.0.1:8799 in the Windows browser (WSL2 forwards localhost).

Things to watch for:

  • gld reads the distribution's ~/.claude. Sessions created on the Windows side (C:\Users\<you>\.claude) are not there: copy the folder, or run CLAUDE_CONFIG_DIR=/mnt/c/Users/<you>/.claude gld (slower access).
  • "Send to the session" requires the session to run inside a WSL tmux; sessions launched from the web interface already open in one.
  • If localhost does not answer, change the port (GLD_WEB_PORT=8800 gld) or enable networkingMode=mirrored in .wslconfig.
