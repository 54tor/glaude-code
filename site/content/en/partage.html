Share a session

Show a session to a colleague without copy-pasting: an invitation link, live following, read-only or read-write, revocable at any time.

Invite someone

  1. Open the session menu (…) and choose Share….
  2. Click Invite someone (the name is optional: "Guest N" otherwise).
  3. The link is copied; paste it into your messaging app.
  • A session can have up to 10 invitations, each with its own link, name, mode and revocation.
  • Each link is single-use: whoever opens it first and presses the button reserves it. Any other browser or device is refused.
  • Regenerate link makes the old one unusable without touching the other guests.
  • The mode is read-only at creation; you grant write access afterwards, guest by guest.

Keep track of guests

The Shared session button in the header (visible as soon as a share exists) opens the list of all invitations: the state of each (connected, away since…, link not used), mode, link, revocation, and the pending guest messages, which you can remove. The badge counts connected guests and pending messages, with no notification.

What the guest sees and does

The guest sees the whole conversation, including tool outputs and background tasks, and follows it live. With write access, they can write to the send queue: gld forwards their messages when the session is idle and no question is displayed on screen. They reach the session prefixed with [Guest <name>]. They can cite project files with @.

They cannot:

  • answer permission requests;
  • open documents or see your other sessions;
  • read configuration files (.json, .yaml, .toml, .ini, .xml…).

In what they read, the absolute paths of your machine, your Claude account name and your git identity are masked; their activity line only shows the tool in progress. They do, however, see the session title as is: rename the session before sharing if needed.

Manage a guest

  • Switch to read-only: they can no longer write and their messages still in the queue are deleted (except the one being sent); they can still remove their own.
  • Grant write access again.
  • Revoke: they lose access immediately and their queued messages are deleted.
  • End sharing revokes all guests.

A browser can join several shared sessions (one invitation per session and per browser): the /guest page lists them (and redirects if there is only one), and an Other shared sessions menu lets them switch between them.

The send queue

It lives on the server, for all sessions: it survives closing the tab. A message being sent at the moment gld restarts shows as uncertain and is never resent automatically; you can relaunch it from the queue.

Limits: 50 messages per session, 32 KB per message, 10 additions per minute per invitation.

Precautions and limits

Sessions without permission prompts. A session launched in auto-accept or bypass mode runs the guest's messages directly: only share it with someone you trust.

  • HTTPS. Without HTTPS, the guest's cookie is not marked Secure: use an HTTPS address if you expose gld.
  • Duration. The guest's cookie lasts 30 days. After Leave, the link is consumed: regenerate one.
  • Testing your own link. If you open it with host access (token, paired device, an account with the exec right on this configuration folder), gld refuses it without consuming it; test it in a private window. In open local mode with no token, opening it consumes it (this browser gets a guest cookie) but does not lock your host interface.
  • No tunnel. gld creates none: your colleague must already be able to reach gld (--listen, reverse proxy or VPN). See Phone and remote access.
  • Sharing works in local mode with no token, in token mode (one user) and in multi-user mode.

Try it without configuring anything

A trycloudflare quick tunnel (no account) is enough for a trial:

cloudflared tunnel --url http://127.0.0.1:8799

It prints an https://….trycloudflare.com address; give it to gld as well (--public-url) so that invitation links use it.

The address changes on every launch (links already sent stop working) and all of gld becomes reachable from the Internet: enable a token or accounts first, and stop the tunnel after the test. This is a trial route, not an installation: it has not been validated with gld.
