Workspace

Review and fix a project's code in the browser: git tree, editor, and a read-only terminal attached to the folder's Claude session.

Open the workspace

The Workspace button in the project view opens the folder in the browser.

Tree and editor

  • A tree with git markers (modified files, new ones…), a filter and a trash.
  • A tabbed editor: Monaco, the VS Code engine, served by gld itself, with no CDN.
  • Ctrl+S saves; Ctrl+P opens a file by name.

A menu (File, Edit, Search, View, Go to, Terminal), an editor action bar, a tree toolbar and a status bar (cursor, line endings, branch, watcher state) give access to everything without knowing the shortcuts.

When the agent modifies the open file

If the agent changed the file in the meantime, a banner asks what to do: reload, overwrite or compare.

Delete safely

Deleting a file sends it to a .gld-trash/ trash in the project, ignored by git. The trash is browsed from the tree toolbar: restoring and emptying happen there.

The read-only terminal

gld deliberately offers no shell. The terminal area, always visible, attaches read-only to a live Claude session in the folder. It is set with GLD_WEB_TERMINAL=1 and only attaches after you have opened it a first time.

Rights in multi-user mode

fs_read is needed to read and fs_write to write, plus exec and sessions_read for the terminal. None is granted by default.

There is no list of forbidden files: fs_read also reads .env and the project's keys. Only grant it to people you trust. See Accounts and multi-user.
