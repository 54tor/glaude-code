Téléphone et accès distant

Suivre ou relancer une session depuis votre téléphone ou un autre poste, être prévenu quand Claude pose une question, et le faire sans exposer votre machine.

Sur un petit écran

La page s'adapte aux petits écrans : le menu passe dans le bouton ☰, et Glaude Code s'installe comme une application (« Sur l'écran d'accueil »).

Ouvrir gld à d'autres appareils

Par défaut, la page n'est visible que depuis votre ordinateur. Pour l'ouvrir depuis un téléphone ou un autre poste :

gld --listen 0.0.0.0

Glaude Code affiche alors une adresse contenant un jeton secret : ouvrez-la telle quelle. Sans cette adresse, la page demande le jeton ; elle porte l'icône et le manifeste, donc l'ajout à l'écran d'accueil d'un iPhone fonctionne depuis elle.

Ne l'exposez jamais directement sur Internet. La connexion n'est pas chiffrée par défaut, et la page peut lire et supprimer vos sessions et lancer Claude. Passez par un tunnel (SSH, Tailscale…) ou servez en HTTPS (plus bas).

Machine partagée : fixer un jeton

Sur une machine partagée avec d'autres comptes, l'adresse locale est joignable par eux aussi. Fixez un jeton (16 caractères au moins) : il est exigé même sans --listen, et gld affiche l'adresse avec $GLD_WEB_TOKEN à la place du jeton, pour qu'il ne finisse pas dans les journaux.

GLD_WEB_TOKEN=$(openssl rand -hex 24) gld

gld --token=<jeton> fait la même chose, mais l'argument est visible de tous dans ps : préférez la variable.

Connecter un téléphone sans recopier le jeton

  1. Sur un appareil déjà connecté, ouvrez Connecter un appareil (icône de téléphone en haut de la barre latérale) : il affiche un code à huit chiffres, valable deux minutes et une seule fois.
  2. Sur le téléphone, ouvrez Glaude Code (l'application de l'écran d'accueil ou le navigateur) et touchez Connecter cet appareil, sous le champ du jeton ou du mot de passe.
  3. Tapez le code : la connexion se fait là où il est tapé, donc dans l'application.

Le même code existe en QR, mais l'appareil photo ouvre alors le navigateur, pas l'application.

  • Le téléphone reçoit sa propre session. En mode jeton, elle dure tant qu'il revient au moins une fois tous les 90 jours, se révoque depuis la même fenêtre et tombe si le jeton change. Avec des comptes, c'est une session du compte qui a affiché le code, visible dans Profil › Sessions.
  • Dix codes faux par minute bloquent l'adresse une minute.

Adresse publique

Le QR code reprend l'adresse de la page qui l'affiche. Si vous l'affichez depuis 127.0.0.1 ou l'IP locale alors que le téléphone passe par un nom de domaine (proxy, tunnel), donnez cette adresse publique :

gld --listen 0.0.0.0 --public-url https://gld.exemple.org   # ou GLD_PUBLIC_URL=https://gld.exemple.org

Avec une adresse publique en https:// sur un nom (ni IP, ni localhost), gld envoie Strict-Transport-Security: max-age=31536000 : le navigateur refusera ensuite tout accès en HTTP clair à ce nom, quel que soit le port, pendant un an. Ne déclarez pas comme adresse publique un nom qui sert aussi un autre service en HTTP.

HTTPS avec mkcert

Sur iPhone et iPad, l'application installée n'a ni notifications (push compris), ni copie native, ni clé de sécurité tant qu'elle est servie en HTTP. gld peut servir lui-même en HTTPS avec un certificat auquel l'appareil fait confiance, par exemple créé avec mkcert : installez son autorité racine sur l'iPhone, puis activez-la dans Réglages › Général › Informations › Réglages de confiance des certificats.

mkcert 192.168.0.10 mon-pc.local
gld --listen 0.0.0.0 --tls-cert 192.168.0.10+1.pem --tls-key 192.168.0.10+1-key.pem

Les variables GLD_WEB_TLS_CERT et GLD_WEB_TLS_KEY équivalent aux deux options. Les clés de sécurité (WebAuthn) exigent en plus un nom de domaine, pas une adresse IP.

Notifications push

Le bouton 🔔 en bas de la barre latérale, à droite de la version, active pour cet appareil une notification quand une session pose une question ou une demande d'autorisation, et quand elle attend votre message. Les deux types se règlent séparément. Elles arrivent application fermée.

  • Prérequis : une page servie en HTTPS avec un certificat auquel l'appareil fait confiance, et, sur iPhone, l'application ajoutée à l'écran d'accueil.
  • Multi-utilisateur : chaque abonné ne reçoit que les sessions des dossiers où il a le droit sessions_read, vérifié à chaque envoi. L'abonnement suit la session qui l'a créé : après déconnexion, révocation, expiration ou changement de mot de passe, l'appareil ne reçoit plus rien ; réactivez le bouton après reconnexion. Un compte a au plus 10 appareils abonnés.
  • Confidentialité : les clés et abonnements sont dans gld-web-push.json (permissions 0600) ; seuls les services push des navigateurs (Apple, Google, Mozilla, Microsoft) sont acceptés comme destination.
  • Limites : un dossier de configuration secondaire n'envoie qu'une fois son processus lancé ; un onglet ouvert ne coupe pas les notifications ; le clic ouvre la session dans le dossier de configuration choisi dans le navigateur (pour une session d'un autre dossier, changez d'abord de dossier).

Restreindre l'explorateur de dossiers

L'explorateur de dossiers (nouvelle session, « Réassigner », « Déplacer ») part de votre dossier personnel et peut parcourir tout le disque. --locations (ou GLD_WEB_LOCATIONS) le limite à une liste de racines séparées par des virgules, chemins absolus ou ~ :

gld --locations ~/Projets,/mnt/data

L'explorateur s'ouvre sur la première racine et ne remonte pas au-dessus d'elle. Les liens symboliques sont résolus avant le contrôle ; un chemin demandé hors racines ramène à la première. Cela borne l'explorateur, pas les droits de Claude Code ni le reste de l'interface.
