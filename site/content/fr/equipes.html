Équipes d'agents

Les équipes d'agents natives de Claude Code, pilotées depuis la page Teams : un chef de projet qui crée des coéquipiers, et vous qui suivez, écrivez et répondez à leurs demandes depuis le navigateur.

Fonction expérimentale. Les équipes d'agents sont une fonction expérimentale de Claude Code, et leur pilotage par Glaude Code n'a pas encore été vérifié de bout en bout sur un lancement réel. Essayez-les d'abord sur un dépôt jetable.

Le catalogue

Glaude Code fournit 21 agents et 11 équipes prêtes à l'emploi. Un agent a un identifiant de rôle (testeur, chef…) et un libellé (« Testeur », « Chef de projet »), sans prénom ; un prénom est tiré à chaque lancement pour chaque coéquipier.

Les agents « lecture » ne reçoivent que les outils de lecture (Read, Grep, Glob) ; les agents « écriture » ont les outils par défaut.

Lancer une équipe

  1. Cochez une ou plusieurs équipes : la composition lancée est l'union des équipes cochées, sans doublon.
  2. Écrivez l'objectif (4 000 caractères au plus) et choisissez le dossier.
  3. Cliquez sur Lancer : gld ouvre la session du chef dans tmux, avec la liste des coéquipiers à créer.

Prérequis : tmux et un lanceur de terminal (par exemple terminator, kitty, wezterm, gnome-terminal, konsole, xfce4-terminal ou tilix) sous le compte qui fait tourner gld. Sans eux, le lancement est refusé, comme sous Windows natif. Un lancement sur une version de Claude Code qui ne gère pas les équipes est signalé « indisponible ».

Le mode de permissions est celui par défaut de Claude Code : rien n'est approuvé automatiquement.

Suivre et répondre

  • L'interface affiche chaque coéquipier sous la forme « Prénom · Libellé de rôle » ; le chef est « Chef de projet ».
  • Messages directs : écrivez au chef (par défaut) ou à un coéquipier. Le message part tout de suite si la cible est inactive et sans dialogue en attente ; sinon il est mis en file (20 au plus par équipe, ordre conservé).
  • Demandes de permission : celles d'un coéquipier s'affichent dans le pane du chef. Vous y répondez depuis la page ; la touche n'est acceptée que si une demande est réellement à l'écran.
  • L'écran affiche « Répondre dans le terminal » quand le chef attend sans demande lisible.

Pour fermer l'équipe, utilisez le bouton de fermeture : il ferme la session du chef et supprime le journal et la file de l'équipe.

Vos propres agents et équipes

Nouvel agent et Nouvelle team créent les vôtres (jusqu'à 200 agents et 100 équipes). Modifier un élément fourni crée une copie personnelle : les éléments fournis ne sont jamais écrits. Un agent utilisé par une équipe ne peut pas être supprimé.

Limites

  • Une équipe par session ; elle prend fin avec la session du chef. Pas d'équipes imbriquées.
  • 3 à 5 coéquipiers sont conseillés : l'interface avertit au-delà de 5, sans bloquer.
  • Le coût en tokens croît avec le nombre de coéquipiers.
  • La file de messages est en mémoire : elle est perdue au redémarrage de gld.

Droits en mode multi-utilisateur

  • sessions_read : voir le catalogue, les équipes et l'écran du chef.
  • exec : lancer, écrire, répondre aux demandes, fermer.
  • config_write : créer, modifier ou supprimer vos agents et équipes.
